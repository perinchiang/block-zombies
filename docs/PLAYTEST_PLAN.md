# 方块尸潮 · 首个街机验证版本计划

> 设计规则已确定，数值需测试，开发尚未开始。本轮只更新文档，不修改代码或玩家存档。
>
> 规则与经济唯一基线见 [GAME_DESIGN.md](GAME_DESIGN.md)；本文记录验证范围、顺序和观察指标，不再比较已经确定的玩法方向。当前可玩的中央广场版仍按 [round.md](round.md) 的搜箱撤离规则运行。

## 1. 首轮范围

**Day 1–5＋一个可重复金币挑战＋具有明显清群能力的加特林。**

| 项目 | 首轮需要验证的行为 |
|---|---|
| 主线 | 配置好的敌群／波次，全部生成并清理后通关；失败重试当前 Day，通关不能回刷旧 Day |
| 金币挑战 | 复用中央广场，可重复，不改 Day，不绕过主线解锁；先一个固定难度配置 |
| 收益 | 普通击杀直接到账并可见反馈；高价值金币包靠近吸附；额外通关奖励单列；死亡保留已获金币 |
| 商店 | 从开始展示首章全部武器的 3D 外观、特色、清怪效果、价格与解锁条件；锁定武器不能提前购买 |
| 武器 | 复用步枪／霰弹，覆盖 Day 3 冲锋枪与 Day 5 加特林规划；重点验证加特林清群和火力成长 |
| 升级 | 暂按 Lv.3 上限、两次明显升级；费用以售价 20%／40% 为起点，免费步枪另设费用 |
| 技术基础 | 复用 Three.js、漫画 Shader、方块角色、导航、现有敌人与武器系统，保持手动瞄准与真实弹道 |

完整随机地图生成器、Day 6–10、章节 Boss、火箭筒可购买实装和换装收集后续完成。首轮沿用中央广场是阶段性复用，不代表最终模式取消章节地图和随机金币挑战。

## 2. 后续开发与验证顺序

以下是下一阶段的工作顺序，不是本轮开发授权。

1. **打通 Day 与收益闭环。** 用明确的敌群配置完成清场判定、失败重试、向前推进，以及三类金币一次入账和死亡保留。替换新模式里的搜箱撤离目标；旧存档迁移先设计好再改，不能直接丢弃已购和旧等级权益。
2. **让金币挑战成为真实的补充路线。** 卡关时能进入固定档挑战，结束后回到原 Day；初版可复用敌群清场结算，不必等随机生成。实际收益能支撑少量重复后购买目标武器。
3. **实现商店购买目标与火力差异。** 接入 Day 门槛、首章武器展示、两次升级和加特林；保持同一挑战配置，用升级前后与不同武器比较效果。
4. **完成 Day 1–5 连续手机试玩。** 观察主动推进、消费、刷钱和获得强枪后的行为，再调整收益拆分、费用与战斗节奏，不通过自动追平装备抵消成长。

Day 5 是该验证版本的主线终点。购买加特林后应能进入金币挑战使用；仅凭重复挑战不能证明玩家愿意继续推进主线，需在后续 Day 6 内容中验证实际继续行为。

## 3. 核心体验观察

| 问题 | 观察内容 | 不能据此直接下的结论 |
|---|---|---|
| 是否愿意连续挑战 Day？ | 自主进入下一 Day、重试、退出位置与原因，是否理解清场目标 | 单次通关或口头喜欢不等于持续兴趣 |
| 是否为加特林主动刷钱？ | 购买目标、前期支出、缺口、主动进入金币挑战及重复次数 | 攒钱直购者不需要刷钱，不能被视为挑战模式失败 |
| 加特林是否明显更强？ | 同一挑战的清群速度、压制能力、移动选择和玩家原话 | 仅伤害数值上涨或机器人胜率不能证明爽感 |
| 买到强枪后是否仍想推进？ | 获得后是否主动再玩，后续有新 Day 时是否回主线 | 首轮只到 Day 5，只能验证继续战斗和推进意愿，不能宣称更高 Day 留存已验证 |

## 4. 经济测试基线

具体收入、累计金额、购枪价和升级价见 [设计文档 §5–6](GAME_DESIGN.md#5-武器商店与成长)。单局约 3 分钟、首章 2,630 金币均为测试目标；总收入包含击杀、实际拾取和通关奖励，不能再叠加一次整张收益表。

首轮至少观察这些路径：

- **攒钱型：**Day 5 累计 930，可直接买 900 的加特林，不强制刷钱。
- **先买霰弹：**Day 5 距加特林还差 210；若霰弹升满则差 354。
- **多枪尝试：**买霰弹与冲锋枪后差 690，观察玩家是否理解选择的成本，而非误以为必须买齐。
- **首章后续：**Day 10 买过霰弹和加特林，距火箭筒差 510；若加特林升满则差 1,050。此路径属于 Day 6–10 扩展后的验证，不能用首轮结果冒充。

建议金币挑战先测试约 3 分钟、总收益 180–240，再按实际完成率和消费路径调整。记录金币／局与金币／分钟、实际拾取损失、失败收入、首次购买时间和主动重复次数。强枪提高效率是预期收益，不应触发敌人自动变强。

重点排查：故意失败当前 Day 是否比金币挑战更划算；升级是否挤掉新枪目标；普通击杀反馈是否清楚；金币包是否造成无聊折返或视觉拥挤。调节敌群和收益配比，不恢复死亡 25% 或故意压低收益制造长时间刷钱。测试不包含广告加成。

## 5. 实现前需补齐的少量细节

已确定的混合奖励、清场通关、Boss 节点和主线购买门槛不再作为候选方案比较。仍需配置的只有：

- 各 Day 的敌群／波次和三类收入拆分；首个金币挑战的具体敌群与结算节奏。
- 免费步枪的两档升级费用，以及各武器升级产生的实际效果。
- 结束时未拾取金币包的处理、退出／中断的存档时机、旧 Lv.4 和已购权益迁移。

这些细节不要求本轮补齐数值或立即实现。

## 6. 技术与真人验收

后续实现需验证：波次间空场不提前通关、最后一名敌人死亡只结算一次、失败不推进 Day、不回刷旧 Day、挑战不改主线进度、锁定枪不能靠金币提前购买、三类收入不重复入账、死亡保留已获金币、重试与刷新不覆盖已有进度。

手机上测试横屏双手移动与射击、自由俯仰、暂停恢复、绕楼追击、镜头避障、密集尸潮与金币反馈下的帧率／发热。记录设备、系统、浏览器和版本。现有自动测试入口在 [round.md](round.md#验证)，新模式未来需要对应回归；桌面模拟和构建通过不代替真实 iPhone 体验。

用版本、Day／档位、装备与等级、局次用时、三类收益、购买与升级、退出／重开及玩家原话记录观察。无需为此先建设后端分析系统。基本闭环可用后可邀请约 5–10 位目标玩家，小样本不作为商业留存或广告意愿的统计结论。
