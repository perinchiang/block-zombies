# 方块尸潮：方向探索与后续试玩计划

> 当前阶段：设计讨论，尚未开始街机模式开发。
>
> 最新方向是“杀怪赚金币 → 完成挑战 → 购买／升级 → 挑战更难关卡”，详见 [GAME_DESIGN.md](GAME_DESIGN.md)。现有游戏仍为中央广场搜箱撤离试玩版，精确规则见 [round.md](round.md)。本文列出可继续讨论和验证的问题，不是自动执行的开发任务表。

## 1. 已确定方向与实现边界

| 方面 | 最新方向 | 当前实现 |
|---|---|---|
| 核心循环 | 街机射击、击杀收益、金币成长；暂搁置搜打撤 | 搜箱、撤离成功全额入账／死亡保留 25% |
| 主线 | Day 逐日推进，每 10 Day 一章共用种子地图；不可回刷已通关 Day | 没有 Day 或章节系统 |
| 重复赚钱 | 独立金币挑战、随机模块化地图、固定难度档位 | 没有独立金币挑战；地图为手工中央广场 |
| 武器与成长 | 首次商店展示昂贵强枪，玩法差异明显，保留永久升级 | 步枪／霰弹枪和 Lv.1–4，本地存档 |
| 外观 | 可配置、保存和复用的程序化角色，逐步扩展部件 | 固定主角，僵尸变体；无完整配置系统 |
| 商业化 | 自愿激励广告，不妨碍战斗和正常通关 | 未接广告；TapTap 发行与接入要求未核实 |

当前地图导航、自由瞄准、真实弹道、受击控制、固定入口和地下预警可作为后续基础。箱子、撤离车、红箱守卫奖励与死亡扣款的替换方式，需要在开发范围确认后处理，不继续把撤离调优当作新方向的主线任务。

## 2. 优先讨论的问题

这些问题可以逐项收敛，不需要为了开始探索就一次决定所有细节。

| 主题 | 待选或待明确内容 | 要得到的判断 |
|---|---|---|
| 击杀收益 | 普通金币直接到账，还是落地后靠近吸附；特殊敌人金币包怎样配合 | 玩家能否感到杀怪有收入，是否出现无聊捡钱 |
| 挑战终点 | Day 与金币挑战各自如何通关或结束 | 玩家是否知道自己在完成什么，时长是否适合手机 |
| 失败收益 | 已到账收益保留；未拾取掉落、退出、中断如何处理 | 收益规则清楚且不会重复发放，失败后愿意再试 |
| 商店目标 | 第一把有玩法变化的新枪、昂贵强枪的展示与购买门槛 | 是否产生明确购买欲，是否理解枪的特点 |
| 成长节奏 | 买新枪与升级旧枪的取舍，主线重试与刷钱档位的效率 | 不两三局耗尽目标，也不被迫低变化重复 |
| 内容范围 | 首轮 Day 数量、挑战档位、候选高级武器 | 选择足够验证循环的内容，不先承诺完整游戏体量 |

每 10 Day 一次 Boss 是候选，尚未确定为强制规则。主线章节种子的分配方式、装备槽和角色编辑工具也可以继续保留待定。

## 3. 后续可比较的试玩方案（建议，未启动）

### 金币反馈比较

在相同敌群、装备和金币总额下比较“击杀直接到账”和“落地吸附”。观察玩家是否知道赚了多少、是否为捡零钱折返、危险与奖励是否清晰、掉落是否挡视线或影响手机性能。特殊敌人高价值金币包可以单独验证，不必先将所有普通敌人改成相同机制。

先明确未拾取金币在通关与死亡时的处理，否则不同方案的收益差异会混淆反馈比较。不要把当前搜箱金币结算直接当成新方案结论。

### 武器欲望与成长比较

先让玩家看到候选强枪的形态与清群能力，记录想买哪把及原因；仅看价格或口头说“很酷”不足以证明购买动力。之后在同一配置挑战中比较基础枪、升级枪与不同玩法武器，观察效率、走位方式和是否主动重开。

价格与产出等到玩法差异有初步证据再调。记录首次购买／升级、目标强枪距离、每局实际收益与用时；检查强枪提升收益后是否使剩余商品过快耗尽。广告不参与基础平衡测试。

### 主线与金币挑战的衔接

观察卡住当前 Day 后，玩家是否自然选择适合的金币档位，买到提升后是否愿意回主线，并能感到同一关变容易。比较主线故意失败与独立金币挑战的收益，避免最优策略变成反复打半局自杀；不通过大额死亡扣款解决。

### 生成地图与角色配置

地图应可按种子复现，检查连通、通道宽度、出生安全、绕行与镜头、敌人追击和异常种子回退；同档随机地图的耗时与收益应相对稳定。地图变化不能只是乱摆建筑。

角色架构可先用少量部件验证配置保存／复用、帽发兼容、材质缓存和闪白恢复，再决定是否制作独立预览工具。换装系统不作为验证杀怪赚金币循环的前置条件。

## 4. 现有版本仍可提供的手机验证

当前中央广场版可以继续测试以下基础能力；这不等于新模式已开发：

- 横屏双手移动与自由俯仰瞄准、按住开火拖动、暂停和恢复输入。
- 绕建筑、十字路改道、贴墙追击与相机避障，固定入口和地下预警是否可辨认。
- 步枪和霰弹的命中反馈、打断与突围体验，以及升级前后的明显差异。
- 连续游戏时帧率、发热、误触和读图负担；记录真实设备与浏览器信息。

现有版仍需按当前规则完成结算；其自动验证入口保留在 [round.md](round.md#验证)。桌面模拟、机器人和构建通过只能证明相应技术检查，不能替代真实 iPhone 或目标玩家体验，也不能证明新经济平衡。

## 5. 反馈记录与范围

建议记录版本、模式／Day 或挑战档位、地图种子、装备与等级、击杀与收益、通关／死亡用时、消费选择、退出／重开及玩家原话。以实际使用到的字段为准，日志和后台分析目前未承诺开发。

形成可玩的新循环并排除明显操作阻断后，可邀请约 5–10 名目标玩家，观察能否独立开始、理解赚钱目标、主动购买和重开、隔天返回。小样本不作为商业留存或广告意愿的统计结论。
