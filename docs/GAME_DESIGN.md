# 方块尸潮 · 游戏设计方向

> 版本 v4 · 街机射击与金币成长方向，尚未开发
>
> 本文描述最新设计方向，不代表当前游戏已经具备这些功能。现有中央广场试玩版仍是搜箱、撤离与结算，准确规则见 [round.md](round.md)。后续讨论和验证见 [PLAYTEST_PLAN.md](PLAYTEST_PLAN.md)，视觉基线见 [style.md](style.md)。
>
> **状态约定**：「确定方向」是本次讨论采用的原则；「暂定建议」可作为比较方案，不是开发承诺；「待讨论／验证」尚未决定。本次只整理文档，不启动游戏开发，也不制定完整数值表。

## 1. 定位与参考

**确定方向：做一款杀僵尸、赚金币、买强枪，再挑战更难关卡的漫画风街机射击小游戏。**

| 项目 | 方向 |
|---|---|
| 平台 | 主攻 TapTap，手机横屏优先；具体发行形态和接入条件待核实 |
| 操作与角色 | 越肩视角、方块角色、主动移动和射击 |
| 核心体验 | 密集尸潮中的走位、火力压制、清群反馈与永久成长 |
| 美术 | 纯代码生成几何部件、材质和程序化纹理，保持漫画化视觉 |
| 经济 | 初期只用金币，买武器、永久升级，未来可扩展装备与装扮 |
| 商业化 | 免费小游戏，未来考虑玩家自愿选择的激励广告 |

参考作品分工：

- **《Call of Mini: Zombies》**：越肩视角、方块角色、武器商店和永久成长。
- **《僵尸危机3》**：密集尸潮、走位、枪械火力与爽快战斗。
- **《翻面 FLIPSIDE》**：漫画化视觉风格；不据此绑定额外玩法或叙事系统。

[《迷你英雄》调研](CALL_OF_MINI_RESEARCH.md)保留为参考，区分原作证据、社区版本与本项目建议；不照搬其角色经验、第二货币、长等级曲线或复杂经济。

### 为什么暂时搁置搜打撤

目前缺少值得搜刮、带出和管理的物资种类，箱子主要只是金币容器。为支撑“搜打撤”再添加材料、背包和撤离损失，会偏离现在最想验证的射击与成长体验。因此暂时搁置搜打撤概念，先围绕金币做清楚循环。

新方向不再以搜箱、决定何时撤离和死亡损失大部分收益为核心。现有代码中的箱子、撤离车和死亡保留 25% 仍是当前版本规则；何时替换由后续开发任务另行决定。地图、导航、射击和受击反馈可以继续作为技术基础。

## 2. 核心循环与战斗原则

**确定方向：**

进入关卡 → 击杀僵尸 → 获得金币 → 完成挑战 → 购买、升级武器与装备 → 挑战更高难度。

失败后保留已经获得的收益，重试当前挑战，或去独立金币挑战积累装备再回来。成长应让曾经吃力的关卡明显变容易；敌人不因玩家升级武器而自动追平。

保留现有自由上下左右瞄准、固定中心准星与枪口真实弹道的操作方向。走位、入口压制、换弹和受击控制应共同形成战斗节奏。强枪可以压住尸群，不因玩家堵门成功而暗中无限加怪；侧向威胁和地下出生需要可辨认的预警与退路。

**暂定建议：**继续以有限弹匣、免费无限备弹作为普通枪械基线，使金币主要服务购买和成长。激光、火箭等武器是否采用不同装填或能量节奏，再按其玩法设计，不先扩展收费弹药经济。

**待验证：**单局时长、尸潮密度、喘息长度、主线通关条件，以及手机手动瞄准在更密集尸群中的负担。目标是火力爽感与移动选择同时成立，不仅靠增加敌人数堆难度。

## 3. 杀怪金币与失败收益

**确定方向：**玩家需要直观看到“我杀怪赚到了什么”；不再沿用搜打撤式大额死亡扣款，已经获得的收益原则上保留。金币获得、永久钱包与结算展示应一致，避免误以为结算又发了一遍奖励。

**暂定方案：**普通僵尸死亡产生清楚的金币反馈，特殊敌人掉落更高价值金币包；采用地面掉落时，玩家靠近自动吸附拾取，不增加逐个点击操作。

普通击杀可比较两种方案，尚未选择：

| 方案 | 可能的好处 | 需要观察的问题 |
|---|---|---|
| 击杀直接到账，配短暂金币动画／数值反馈 | 战斗不断流，收益明确，不必折返清理战场 | 是否缺少接近奖励的满足感；反馈是否被尸潮淹没 |
| 掉落金币，靠近吸附后到账 | 金币具象可见，走位与奖励位置产生联系 | 是否变成绕场捡零钱；密集掉落是否遮挡敌人或拖慢手机 |

特殊敌人金币包可提供更强的奖励辨识，但是否与普通金币采用不同结算方式仍待测试。

**待讨论／验证：**吸附距离、地面存留与合并显示、通关或死亡时未拾取金币如何处理、主动退出和中断时的保存时机。必须先定义“已获得”的边界；已到账收益保留，不等于已经决定所有地面掉落也自动带走。存档需避免重复入账或重试覆盖已赚收益，具体实现后续设计。

## 4. Day 主线

### 确定方向

- 采用 Day 1、Day 2、Day 3……逐日推进。
- 每 10 个 Day 构成一个章节，同章节共用一张通过种子生成的地图。
- 同章节逐步增加敌人数量、种类、组合和挑战难度；熟悉地形后面对新的战斗要求。
- 主线只能向前推进；失败可以重试当前 Day，通关后不能返回旧 Day 刷金币。
- 难度来自关卡配置，不读取玩家武器等级来自动补偿敌人强度。
- 主线卡关时允许去独立金币挑战成长，之后回来继续当前 Day。

### 暂定建议

每 10 天安排一次 Boss 战，作为章节高潮和装备检验。Boss 是否必设、是否混合普通尸潮、奖励形式均未定；现有恶魔可用于讨论攻击预警与控制窗口，但不等于已确定它就是每章 Boss。

### 待讨论／验证

- Day 以清完指定敌群、生存一段时间还是其他明确目标通关？不直接照搬参考游戏的收入阈值。
- 章节种子是统一预设、每份存档生成一次，还是其他分配方式？同章重试应能复现地形，不能每次失败都偷偷换图。
- 首轮需要做多少 Day、多少章节，何时引入新敌人？尚未承诺内容总量。
- 失败保留收益与当前 Day 可重试结合后，故意失败可能成为刷钱方式；应比较收益效率，避免它压过专门的金币挑战，也不因此恢复大额死亡惩罚。
- 是否有额外通关奖励及其发放规则？若采用，应与击杀收益分开显示，并防止重复领奖。

## 5. 独立金币挑战与地图生成

### 确定方向

金币挑战独立于主线，可反复进入，不改变当前 Day。使用随机地图种子和模块化场景拼装，提供固定难度档位；同一档敌人强度和预期收益相对稳定，方便玩家选一个适合当前装备的档位赚钱。

难度档位不随玩家升级自动变强。随机地图改变交战空间和路线，不应让同档收益与耗时大幅失控。更好的武器应该让熟悉的档位打得更快、更轻松，而不是每次成长都被抵消。

### 暂定生成架构

先生成可通行的道路关系，再装配建筑、掩体和装饰；模块包含道路连接口、占地、碰撞、出生候选点和可用战斗空间等信息。地图种子与难度配置分别负责空间和敌人挑战，便于复现问题。

生成结果需要验证：

- 玩家出生区域、目标区域和必要道路互相连通，连接口没有视觉连通但碰撞封死的问题。
- 按角色碰撞体检验通道宽度、转角、退路和敌人导航；不能仅检查地图格子相邻。
- 刷怪点可通向战斗区域，有合理安全距离和可读的来敌方式；地下出生不直接造成无预警贴身伤害。
- 建筑、掩体与奖励点不互相重叠到无法通行，镜头能在主要道路工作。
- 极差结果有重新生成或回退地图的办法；具体规则和性能预算待验证。

现有中央广场是手工布局，**尚不具备这套模块化随机生成系统**。它可作为模块尺寸、绕行和刷怪规则的参考，不绑定所有新关卡都必须有中央广场。

### 待讨论／验证

金币挑战的结束条件、档位数量、开放条件、每档预期时长与奖励构成；是否允许提前结束，以及未拾取收益如何结算。随机种子不能成为抽到好地图才值得玩的刷钱机制。

## 6. 武器商店与长期购买欲望

### 确定方向

玩家第一次打开商店就能看到一些厉害、昂贵、值得期待的武器；即使暂时买不起，也能理解它们为什么值得买。保留永久武器升级和金币一种货币，暂不加入角色经验等级、第二货币或复杂改装。

高级武器必须带来明显不同且夸张的战斗体验，例如持续压住密集尸群、大范围爆炸、一发击穿多个敌人。不能只换模型、提高伤害数字，也不能给所有强枪相同的限制使它们体验趋同。

### 候选武器与玩法差异（暂定，不是完整开发清单）

| 武器 | 希望卖给玩家的体验 | 可讨论的操作节奏或取舍 |
|---|---|---|
| 步枪 | 稳定连射、移动中处理多个目标 | 均衡基线，供比较升级效果 |
| 霰弹枪 | 近距离一枪打散包围，腾出空间 | 射程与重新开火间隔形成选择 |
| 加特林 | 长时间扫射、持续压住大片尸群 | 起转或移动负担可作为候选，不能削掉压制快感 |
| 火箭筒 | 一发在密集尸群中炸出大缺口 | 装填间隔、瞄准落点；是否有自伤尚未决定 |
| 激光枪 | 成束贯穿或扫过多只敌人 | 连续光束或单发穿透两种方向待选，不能据此默认可穿建筑 |

加特林、火箭筒和激光枪是目前的强枪愿景，尚未决定全部上线、先做哪把、价格或解锁 Day。每局带几把、是否局内切枪也仍待讨论。

### 商店呈现建议

在首页展示可追求的高级武器、金币价格、玩法说明及明确的获得条件。优先用程序化模型预览或短演示说明“能怎样清怪”，而非堆砌属性。是否增加免费靶场或限时试用后续测试；广告试用不能成为理解武器的唯一方式。

武器从首次进入商店就可见；**可见不等于已决定购买门槛**。只要金币足够即可购买，还是部分武器另需主线进度，仍需讨论。

### 永久升级

确定保留永久成长，让同一挑战在升级后明显更好打。暂建议围绕每把枪的特性选择升级收益，避免所有武器共用一条失去特点的数值曲线。升级应与攒钱买新枪形成有意义的选择，不能让每次小升级都把远期购买目标拖得遥遥无期。

当前两枪 Lv.1–4 和既有价格只属于现有试玩版，不作为新经济的固定约束。新版本等级上限、升级属性、是否保留同样档数以及旧存档如何过渡均待决定；不在这次文档中改动或清空现有存档。

## 7. 金币经济：先验证购买节奏，再定数值

**确定方向：**避免两三局买完全部内容，也避免靠重复低变化战斗把价格硬拖长。死亡保留收益、主线不回刷、金币挑战可重复，是经济设计必须同时满足的条件。正常成长以不看广告为基线。

**暂定建议：**用“距离下一个有吸引力的选择还有多少局”衡量价格，而非单看价格数字。早期提供能感到变化的购买或升级，中期出现玩法不同的武器，昂贵强枪保留较长目标；具体需要几局不先定。

| 要比较的量 | 用途 |
|---|---|
| 各档实际金币／局、金币／分钟 | 同时计入失败、换弹、走位和拾取，不只看理想全杀收益 |
| 首次购买、首次升级、首把高级武器的到达时间 | 检查前期是否无反馈，或内容是否过快耗尽 |
| 买新枪与升级旧枪的成本、实际战斗收益 | 检查是否存在唯一正确的消费顺序 |
| 强枪解锁后的清关速度与收益变化 | 允许成长加快赚钱，同时检查后续商品是否瞬间失去目标感 |
| 主线重试与金币挑战的收益效率 | 检查故意失败是否成为最优刷法，固定档位是否值得玩 |
| 玩家愿意重复的次数、退出原因 | 区分“想攒钱”和“被迫刷钱”；金币产量正常不代表过程好玩 |

价格与升级成本应结合各阶段可获得的收益一起调整。可以用“剩余购买金额 ÷ 当前可持续的每局净收益”粗估所需局数，再用真实失败率与玩家感受纠正。此处不设完整价格表、收益表或广告倍率。

**待讨论／验证：**特殊敌人金币包与普通击杀的占比、通关奖励是否必要、各档收益梯度、购买和主线门槛、装备与装扮对武器预算的分流。若感到无聊，先检查战斗变化与目标吸引力，不能只加价格延长寿命。

## 8. 模块化方块角色生成器

### 现有能力（源码核对）

已检查 [blockman.js](../src/actor/blockman.js) 与 [faces.js](../src/actor/faces.js)：

- `BlockMan` 使用刚性方块、`Group` 层级和关节旋转组成身体、头与四肢，没有蒙皮或外部模型。
- 构造参数只有 `kind`、`variant`；僵尸有 8 个变体，主角外观基本固定。
- 身体几何与按 `kind:variant` 缓存的材质可复用，但皮肤、头发、上衣、裤子配色依赖固定调色板。
- 主角头发是头顶与后脑的几何块；`heroFace()` 又将固定刘海画进脸部纹理，换发型不能只替换几何块。
- `faces.js` 用 Canvas 生成脸部和衣服纹理，`heroJacket()` 的底色、拉链和口袋固定，僵尸脸部／破衣由种子变化。
- 枪械装配、枪口位置与等级条带也在角色类中；受击闪白依赖构造时遍历得到的 mesh 列表。新增或替换部件要维护材质恢复逻辑。
- 当前没有完整的外观配置保存、部件目录、帽盔或背包装配系统，也没有独立角色编辑工具。

### 确定的扩展方向

通过组合现有 Three.js 几何、材质和程序化纹理，逐步支持发型／发色、帽子／头盔、上衣／裤子及配色、背包／战术背心。角色外观配置需要能保存和复用，不依赖外部模型。当前只规划架构，不一次实现所有换装部件。

### 建议的职责划分（尚未实现，接口名未定）

| 层次 | 职责与边界 |
|---|---|
| 外观配置 | 可序列化的数据，记录版本、部件标识、配色和必要的外观种子；不保存 Three.js 对象 |
| 部件目录 | 发型、头饰、衣裤、背包等的几何／纹理构建规则及兼容信息；ID 稳定，缺失部件有默认回退 |
| 角色装配 | 沿用现有头、躯干与四肢支点，为头饰、胸前和背部提供挂点；外观变化不随意改变移动碰撞体或枪口 |
| 材质与纹理 | 让皮肤、头发和衣物颜色可参数化；把刘海与脸部表情的职责拆开，防止换发型后旧刘海残留 |
| 动画与表现 | 延用现有走路、瞄准、后坐力和闪白；换部件后正确登记 mesh 和原材质，避免不闪白或恢复错误 |
| 装备属性 | 功能装备的属性独立于纯外观；同一配置不直接把任意显示字段当成战斗数值 |
| 存档与复用 | 保存选中的配置和拥有状态，支持默认角色与命名预设；迁移、购买校验和编辑器导出格式后续再定 |

共享资源缓存需按实际外观参数区分，避免改一个人的颜色影响其他角色；限制组合产生的材质、纹理与 draw call，并明确资源释放归属。帽盔与头发的遮挡、背包与武器的穿插应有兼容规则，具体规则不用在这轮定死。

**未来候选：**独立角色预览／编辑工具，可旋转观察、切换动作、组合配色和部件、保存／载入配置。先使同一配置能在游戏与预览中一致生成，再决定是否做完整编辑器。

装扮可用于金币购买与收藏；部分功能装备可提供适度属性差异。哪些部件纯装饰、哪些带属性、装备槽数量以及属性上限尚未确定，不把头盔或背心的外形自动等同于已决定的护甲系统。

## 9. 商业化与范围

**确定方向：**免费小游戏，优先玩家主动选择的激励广告。广告不打断战斗，也不是正常通关和购买强枪的必要条件。

**候选位置：**结算时领取额外金币、试用高级武器。是否采用、倍率、试用时长、次数和试用收益规则均待讨论；此前的广告复活、每日补给等想法不作为已确定方案。

平台核实前不承诺 SDK 能力或收益。TapTap 发行方式、广告 SDK、接入资质、平台要求与分成仍需后续核实；当前 Three.js 项目也不因主攻 TapTap 而默认迁到 TapTap Maker。

角色经验、第二货币、复杂改装、搜刮材料、实体安全屋、幸存者、漫画结算分享、排行榜和联机暂不纳入本轮方向的必做范围。旧设想可以以后重提，不以此填满新方案或排成既定开发路线。

## 10. 下一步讨论边界

当前已确定的是街机射击与金币成长方向、Day 主线结构、独立金币挑战和可扩展角色外观目标。尚未决定的核心问题包括普通金币如何到账、挑战如何结束、强枪如何解锁、购买／升级节奏与首轮内容范围。

先围绕这些问题形成可比较的小方案，再另行确认开发范围。现有版本可继续验证触控、走位、反馈和性能，但不能把它的搜箱撤离结果当作新循环已经验证。本文件更新不意味着自动开始开发任何新模式、武器或换装系统。
