# 方块尸潮（暂定名）

方块小人越肩视角打僵尸，手机横屏优先。画面由代码生成，没有外部图片、模型或音频资产；本批资产不变。

当前已实现 **Day 1–2 固定波次清场基础**：复用 40×40 米中央广场地图、四个建筑岛、双向外环与十字通路。每 Day 三波，清除所有计划敌人后通关；击杀直接赚金币、特殊金币包自动拾取、通关额外奖励，死亡保留已到账收入。失败重试当前 Day，已通关 Day 不可回刷。没有搜箱、撤离车或计时胜利。

| 当前关卡 | 敌人数 | 击杀收入（每只 3） | 特殊金币包 | 通关奖励 | 完整通关总收入 |
|---|---:|---:|---:|---:|---:|
| Day 1 | 20 | 60 | 20 | 40 | 120 |
| Day 2 | 26 | 78 | 24 | 48 | 150 |

每关最后一波的最后一名计划敌人带金色标记，死亡掉落金币包；不一定是最后被击杀的敌人。开局等待 1 秒，波次清完后间隔 5 秒。未生成队列或活怪未清空都不会通关。Day 2 后显示完成及“后续关卡制作中”，没有 Day 3；未拥有霰弹枪时仍可免费试用，试用零收入、零进度，不是金币挑战。

完整验证版本的后续基线仍为 **Day 1–5＋可重复金币挑战＋加特林**。当前已完成 Day 1–2 基础与最小可重复金币挑战；Day 3–5、冲锋枪、加特林、爆头、连击、随机地图均未实现。见 [设计与经济基线](docs/GAME_DESIGN.md)、[验证计划](docs/PLAYTEST_PLAN.md) 和 [当前规则](docs/round.md)。

在线预览：https://perinchiang.github.io/block-zombies/ （main 推送后由 GitHub Actions 部署；工作区实现不代表线上已更新）

## 运行与操作

```bash
npm install
npm run dev          # http://localhost:5191 ，同一 Wi-Fi 的手机可用局域网地址打开
```

- 手机横屏：左半屏摇杆移动，右半屏拖动自由俯仰与转向；按住开火可同时拖动瞄准。
- 电脑：WASD／方向键移动，点击画面锁定鼠标后自由瞄准，左键／空格开火，Q/E 转向。
- 准星固定在屏幕中心，弹丸从枪口以 48 m/s 飞向瞄准点；无自动选敌或吸附。弹丸按三维扫掠首碰撞命中，场景挡弹；穿甲仅可穿敌人。
- 右上角暂停键／Esc 查看 Day、波次、金币收入、武器和 buff；暂停冻结战斗与拾取，恢复时清空按住的输入。首次教学在同一浏览器只显示一次。
- 贴墙时镜头滑到眼睛高度或换到左肩，不会被主角自己挡住。击杀处弹出金币数字，金币飞回主角；HUD 右上角显示当前武器图标。
- 普通怪和跑者绕障追击；当前战役不生成恶魔。五种限时 buff、受击控制和自由瞄准沿用现有系统。

## 商店与存档

步枪免费。新购买霰弹枪需 **通关 Day 2 且支付 240 金币**；旧档已拥有的霰弹枪保留使用权，不受新门槛追溯限制。两把枪仍可按 **60/120/220** 金币升到 **Lv.2/3/4**。未来 Lv.3 上限与新费用仍是提案，本批不截断旧 Lv.4。

未拥有的霰弹枪可免费试用，固定 Lv.1；胜负均零收入、不推进 Day、不改变已购或保存的装备。当前通关 Day 2 后不能回刷主线；购买霰弹枪不会开放后续 Day，但可带入金币挑战使用。

**金币挑战已实现**：从首次打开商店即可通过 `shop-challenge` 按钮重复进入，复用同一地图和 Day 2 的三波 26 敌人。完整清场收入为 **78 击杀＋24 金币包＋48 通关＝150**；失败保留已获收入。`mode: challenge` 不改变 `completedDay`，也不绕过霰弹的 Day 2 购买门槛。先花 60 升级步枪时，两关后余额为 210，可通过挑战补足 240 购枪价；免费霰弹试用仍零收益，与此模式不同。

正式局击杀与实际拾取即时记入钱包，通关奖励只发一次，结算合计不再重复发钱。金币包在 2.5 米内自动拾取，5 米内开始吸附；胜利自动收取剩余包，死亡未拾取的包丢失。钱包上限 1,000,000。

存档内容为 **v3**，沿用 `block-zombies.profile.v1` 键，增加 `completedDay`（0–2）。迁移 v1/v2 保留钱包、已购和装备；v1 补 Lv.1，v2 完整保留已有等级（包括 Lv.4），旧档主线从 Day 1 开始。localStorage 仅限当前浏览器／设备，无云同步；读取或写入失败回退会话存档并提示，未知版本不覆盖。

## 调试与验证

- `?skip` 跳过开始面板；`?auto` 战斗机器人（按准星而不是按主角朝向瞄准），`?auto=weak` 弱档；`?speed=2` 加速。
- `?fps` 显示帧时间与敌人数；`?still` 定格截图。
- `?shade=flat` 纯墨块阴影对比；`?cam=x,y,z&look=x,y,z` 试镜头；`?inspect=角度,距离,高度` 绕主角看模型（0 为正面）。

无需浏览器：

```bash
node tools/campaign-test.mjs
node tools/profile-test.mjs
```

启动 dev server 后运行 `node tools/day-campaign-test.mjs`，检查战役与收入闭环。其余有效回归入口：`navigation-test`、`combat-reaction-test`、`aim-test`、`camera-test`、`buff-test`、`touch-test`、`pause-test`、`encounter-test`、`loadout-test`、`shop-test`（均在 `tools/`，后缀 `.mjs`）。`combat-reaction-test` 仍有独立恶魔控制测试，不表示战役会生成恶魔。旧 `extraction-test`、`central-square-test` 已移除。构建：`npm run build`。

截图：`node tools/shot.mjs "?still" shots/a.png --w=844 --h=390 --dpr=2 --mobile`（需 dev server）。上述为验证入口，不宣称本次运行了全部测试。

Patrick 曾反馈核心战斗“好玩”；历史试玩和桌面模拟不能证明新循环、真实 iPhone 操作、帧率或发热已验证。约 3 分钟是后续节奏目标，不是当前实测时长或胜利计时器。

## 定位

- 越肩射击、杀怪赚金币、购买升级后挑战更难关卡。参考《Call of Mini: Zombies》的视角与成长、《僵尸危机3》的尸潮与火力、《翻面 FLIPSIDE》的漫画视觉；主题、角色、地图自行设计。
- 强线条漫画风：纸白底、黑描边、平涂与硬阴影，见 [style.md](docs/style.md)。
- Vite + three.js，先验证手机网页版，再考虑 TapTap。

[《迷你英雄》调研](docs/CALL_OF_MINI_RESEARCH.md)作为历史参考保留，当前实现以 [round.md](docs/round.md) 为准。
